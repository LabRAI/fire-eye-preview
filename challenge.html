These are the proposed safeguards for the future model track. No official round is open.

Same task

Predict active-fire occupancy on the native 5 km land grid for four 12-hour windows. Keep each lead and geographic slice visible.

03

Observed outcomes

Use versioned satellite labels and explicit observation masks. Unknown cells stay unknown. Incident discovery reports form a separate analysis.

04

Reproducible results

Lock model and input hashes, compute limits and evaluation code. Publish sample counts, uncertainty and a dated result record.

How scoring will work

Proposed primary measure: observed positive-cell capture within the highest-ranked 20% of eligible land area, with proportional treatment of score ties. PR-AUC provides a supporting view once defensible positive and negative labels are defined. Mask unknown coverage; do not score windows with no eligible positive cells. Pool only predefined rounds with explicit weights and report uncertainty across windows.

Historical backtests and future rounds have separate standings. The future round must lock entries before its first input issue, with all forecast outputs recorded before their corresponding windows begin. Pre-existing fires and newly observed activity should also be reported separately.

Sign-in, models and privacy

GitHub sign-in connects to the existing pseudonymous Fire-eye account. This prototype stores model drafts only in page memory. The future service would use separate private artifact storage and an isolated evaluation queue. Public results would show a chosen model label, never a GitHub profile or private model weights.

Supabase remains limited to pseudonymous account/session identifiers and behavior records. Model metadata, artifacts, jobs and detailed results need their own storage. The website remains usable if an evaluation worker is unavailable.

Prediction format & timing

Fill the template with your model's 0–1 scores in row-major order. All reference land cells require a value; ocean / NoData cells may remain null. Grid CSV supplies cell-centre coordinates and the reference land mask. Both models are compared at 0.001 precision.

The public receipt must be confirmed before the entire 12-hour window starts. Allow at least 20 minutes for collection and publication. A filename or self-reported issue date is not proof of an early prediction. Late submissions cannot enter the prospective comparison.

Submit a prediction file

Upload a prediction JSON (up to 60 KB). Validation happens in your browser; submission is completed through GitHub.

Submit on GitHub ↗

After copying, paste into the GitHub form and submit. A GitHub account is required. Predictions, model labels and issue activity are public. Uploading here alone does not create a receipt; check your submission below.

How comparison works

After a 72-hour reporting allowance, we compare how many documented wildfire-discovery cells fall inside each model's highest-ranked 10% and 20% of the same land area. Ties receive proportional weight. Results are refreshed through day seven.

This first track uses NIFC/WFIGS wildfire reports and excludes prescribed-fire records. Discovery reports are not a full satellite-occupancy target. Unreported cells are not verified fire-free cells; no overall accuracy, false-alarm rate or probability calibration is inferred. Participants may submit after the reference issue and use later inputs; this is a paired case comparison, not a controlled equal-lead benchmark. Different submitted regions are not pooled into a leaderboard.

Submissions & comparisons

The collector runs independently every ten minutes. Forecast values and receipts are retained when observations or publication are delayed. The live map does not wait for this evaluation.
